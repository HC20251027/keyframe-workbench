# 方法论深入：关键帧工作台背后的工程方法

本文件展开 SKILL.md 中点到为止的部分。目标读者：执行本 skill 的 AI 与想改模板的人。

## 一、为什么"帧 = 纯函数"是地基

控制台的一切能力（拖键即时生效、零漂移验证、确定性渲染、帧序列预览）都建立在"同一份参数下 `renderAt(t)` 永远产出同一帧"之上。落实手段：

- 所有随机性走**带种子的稳定哈希**（如 `boilSeed(name)` + `jit`/`hash`），种子来自元素名，不来自时间或调用序。
- 不用全局可变状态存动画进度；镜头内的局部时间 `lt = t - shotStart` 从数据层算出。
- Web 端 `requestAnimationFrame` 渲染循环与导出端（headless Chrome 单帧调用）共享同一求值路径。

## 二、数据层抽取：从硬编码到 PP.keys 的安全路径

动画先以硬编码形态过 QA（这是创作自由度最大的阶段），然后按以下步骤抽：

1. **逐条登记**：每个 `kf(t, [[t0,v0],[t1,v1],...])` 调用登记为一条轨，命名带镜头号（如 `seaB`、`camZA`），`row` 字段给轨道条分行用。
2. **推清数学**：确认原曲线每段的确切插值。常见陷阱：
   - `kf()` 默认每段 smoothstep；`seg()` 是纯线性；`ease(seg(x))` 与 `ease(ease(seg(x)))` 差一整档——数据层必须区分 `'ss'` 与 `'ss2'`。
   - **末键时间写成 `dur`（镜头时长）而不是绝对时间**会导致求值扫描永不命中、恒返末值——旧成片里这条"回落 ramp"可能从来没发生过。按零漂移铁律，把**实际行为**（含台阶跳变）固化进数据层（用同时刻双关键帧表达，`kf` 扫描逻辑下无除零风险）；要改回叙事意图是创作变更，单独过门。
3. **PK 求值器**：复现原 `kf` 的分段扫描结构，按轨的 `e` 字段选插值。要求与原公式**位级一致**（可用 Python 逐点复刻 JS 浮点运算做位级对比）。
4. **镜头注册**：`shots(PP.keys.shots.map(...))`，注册函数做成幂等替换（push+sort 会叠条目，拖切点重复注册就崩）。

### 零漂移验证法（标准作业）

```bash
# 改代码前：渲染参考帧（覆盖所有插值模式、镜头边界、不连续点）
render_pv.py --stills "0.2,1.0,...,14.8" && mv out/hero/t*.png out/verify/ref/
# 改代码后：重渲同批时刻，逐像素对比
```

- 判定：差异像素占比 ≤0.15% 且单通道差 ≤15 视为抗锯齿噪声（SwiftShader 环境的既有本底）。
- 超门时的定位顺序：① 同代码双渲染排除管线非确定性 → ② 差异热图看是哪个几何元素在动 → ③ Python 位级复刻 JS 浮点逐轨对比 → ④ 逐条核对数据层的插值模式与关键帧时间。
- 经验值：本底噪声约 1-30px；插值模式标错（如 'ss' 标成 'ss2'）会造成数万像素的局部大面积差异且集中在该曲线驱动的元素上。

## 三、原则检查器：把动画师的基本功显式化

专业动画师改任何一处都会下意识检查三类原则——把这套下意识做成机器可查的规则表：

- **居中**（主体与观众视线焦点）：光效时序 vs 情绪拍点对位、视线引导。
- **连贯**（镜头间衔接）：相机缩放跨切点衔接、转场与切点锚定。
- **完整**（叙事结构完整）：会破坏已验证节奏结构的改动。

实现：`PV_RULES = [{test(id), p, msg}]`，编辑操作层每个动作返回 `conflicts`，UI 点亮对应球并列出具体冲突。**只提示，不阻止**——裁决权在人。规则表按项目写（模板里是《灵锚》示例）。

## 四、控制台交互层（AE 惯例的落点）

| AE 概念 | 模板实现 |
|---|---|
| Dope Sheet | 轨道模式：帧×轨道矩阵，菱形=键，横向拖=retime |
| Graph Editor | 曲线模式：值曲线按真实插值逐点采样绘制（lin/ss/cin 形状真实可见），拖点改 t/v |
| J/K 跳关键帧 | 按时间排序的唯一关键帧时刻表上下跳 |
| CTI 播放头 | 贯穿全轨的红色竖线，压中的键高亮琥珀色 |
| U 键浮出有键属性 | `?sel=轨id` 直达该轨曲线模式 |
| 区间 retime | 框选区间→拖手柄，开区间内所有键+拍点等比映射，区间外不动（"这段快一点"的可控语义） |
| 拍点 marker | 可拖动的表演时刻标记，不出镜头边界 |

编辑操作层 `keys_edit.js` 的 API（UI 与自动化测试共用，保证行为一致）：`setKey / addKey / delKey / revertTrack / setBeat / setShot / retime / keysPatch / applyPatch / acceptAI / restoreKeys`。补丁形态：轨级最小 diff；**shots 必须整组给出**（合并器对 shots 是整体替换，半组会丢镜头）。

## 五、性能手法（为什么这样做）

1. **帧序列直读**：成片导出时顺手转 JPEG 条（quality 82 约 80KB/帧，15s 全片 29MB）。预览=换 `<img>.src`，秒切、满帧、满画质；现场全画幅重渲单帧 1-3 秒且阻塞主线程，只配当兜底。**帧文件名 5 位编号 `padStart(5,'0')`**——4 位曾让路径对不上、直读静默失效，用户端表现"卡飞"。
2. **事件委托到稳定父容器**：SVG 经常 innerHTML 全量重建，挂它身上的监听和 `setPointerCapture` 会被一起删掉（隐性 bug：拖到一半事件丢失）。挂在 `#tlWrap` 这类不重建的容器上，配合事件委托找 target。
3. **rAF 合帧**：`pointermove`（高回报率输入，每秒 200+ 次）只存坐标，实际重排/renderTL 挂 rAF，一帧最多执行一次。
4. **增量更新**：拖单个键只改那个节点的 `transform`/属性；全量 SVG 重建（~150 节点+240 点曲线采样）只在松手时发生。
5. **rAF 时间累加器播放**：`cur += dt * FPS * spd`，追帧上限 2s；setTimeout 驱动会漂移且与显示刷新不同步。
6. **去重与缓存**：同帧号不重复换 src；镜头 chip 与菱形高亮列表在渲染时缓存成数组，播放循环里不再 `querySelectorAll` 扫树。

## 六、验证控制台本身（三道门）

1. **UI 截图门**：headless Chrome（SwiftShader 旗标）截轨道/曲线双模式，核对 CTI 位置、键高亮、属性面板、镜头徽章联动。
2. **编辑操作层门**：自动化测试页（与生产共用 keys_edit.js）全 API 断言，核心断言是**可逆性**：改键→渲染出大差异→拖回去→回噪声级。
3. **确定性门**：同参数三连跑像素级一致（差异只允许出现在引擎本底噪声区）。

## 七、踩坑实录（都是真实发生过、花了真实时间定位的）

1. **预览帧编号位数错位**（5 位文件名 vs 4 位请求路径）：功能静默失效，无报错，每帧走重渲兜底。教训：路径生成与磁盘产物必须用同一命名函数/同源测试。
2. **重写 UI 丢内部同步函数**：启动即 ReferenceError 死在半路，但已渲染的半边 UI 看起来正常——极具迷惑性。教训：重写不是从零写，旧函数逐个迁移打勾。
3. **测试快照时序错误伪装成引擎 bug**：改完数据才拍快照，"还原后不一致"其实是快照本身脏了。教训：先拍快照后改数据，断言失败先怀疑测试自身。
4. **测试页忘引渲染依赖**：`setup` 永不执行、无报错。教训：测试页与生产页共享同一份 `<head>` 依赖清单；探针打到报告区（booting/READY）而不是靠猜。
5. **headless 虚拟时间预算小于等待循环**：截图永远黑屏/空状态。教训：等待循环时长 < 虚拟时间预算，两者都要显式写。
6. **p5 画布是 flex 布局污染物**：4 个默认 canvas 挤占 stage 弹性空间。解法：`main canvas { display:none !important; }`（composite 用的离屏绘制不受影响）。
7. **引擎硬依赖 `<canvas id="out">`**：没有它 `getContext` 抛异常、ready 永假。模板已内置隐藏画布，自己搭壳时别漏。
