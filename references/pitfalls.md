# 做代码渲染动画时踩过的坑

这份是实操记录，不是教程。每条按 **症状 → 根因 → 解法** 写，都来自真实返工。
适用场景：用代码逐帧渲染一支片子（canvas / WebGL + headless Chrome + ffmpeg），
尤其是画面里带手绘质感、文字、以及"每帧都要重画"的那种。

---

## 一、渲染管线

### 1. ffmpeg 读帧序列遇到缺号会静默停止（**会毁片**）

- **症状**：成片比预期短、尾部内容被截掉，但 ffprobe 不报任何错。曾经 648 帧的片子只出了 639 帧。
- **根因**两层：① headless Chrome 截图偶发失败，返回值被直接丢弃，没有重试也没有告警；
  ② `ffmpeg -i frames/f%05d.jpg` 是序列输入，**遇到第一个缺号就结束读取**，剩下的帧全部不编。
- **解法**：
  - 截图失败必须逐帧汇总并报出来，不能吞；
  - **编码前扫描帧序列连续性** —— 编号无缺口、没有 <1KB 的异常小文件。
    这是唯一能拦住"静默丢帧"的位置，编完再查就晚了。

### 2. `spawn('ffmpeg')` 在 Windows / Git Bash 下找不到可执行文件

- **症状**：路径明明存在、`PATH` 也设了，子进程仍报 not found。
- **解法**：别在渲染脚本里依赖裸命令。改走 **渲染帧序列 → 显式绝对路径调 ffmpeg 编码**。
  附带好处：链路可断点续渲、可先验帧连续性、出错点清晰。

### 3. 并行渲染要求每一帧都是时间的纯函数

- **症状**：并行渲出来的帧偶发"串帧"（这一帧带了上一帧的元素）。
- **根因**：帧是乱序、多 worker 渲染的，任何跨帧状态（累积变量、上一帧缓存、全局随机流）都会串。
- **解法**：所有随机性走**场景内确定性播种**（`boilSeed(唯一key)`），每帧从头算一遍，
  不读任何"上次剩下来的东西"。随机 key 必须稳定 —— 同一元素每帧要用同一个 key。

## 二、手绘字（中文）

### 4. p5 2.x 移除了 `loadFont` / `textToPoints`

- **症状**：想"把字形拆成描边点、再用笔触描一遍"（真笔触描字），发现 API 没了。
- **解法**：这条路封死，改走**像素级技法**：
  洇墨底（模糊+低透明）→ 多道叠印（第一道实心墨骨，后几道毛边）→ 噪声侵蚀（飞白）
  → 逐字抖动 → **横带切片变形**（把字切十几条横带，每带随重画帧位移+横向缩放，字骨架才真的在动）。
  全部按每秒 12 次的重画节拍播种，和笔触同一个沸腾节奏。

### 5. `destination-in` 的 `globalAlpha` 乘在"源"上

- **症状**：想让"噪声低的地方被削弱、留着高光当飞白"，结果整片墨色发灰。
  设 `erode = 0.3`，实际抹掉了 70%+ 的墨。
- **根因**：`destination-in` 的 `globalAlpha` 乘在**源**（噪声图）上，于是 `a' = a * (k * noise)`，
  整片被等比压暗，不是"只削弱噪声低处"。
- **解法**：另做一张**反向噪声图块**（alpha = 1 − 噪声），用 `destination-out` + `globalAlpha = k`，
  得到 `a' = a * (1 − k * inv)`，才是要的效果。

### 6. `drawImage` 四参数重载会把整块画布缩进目标矩形

- **症状**：逐字合成的字被挤小、变灰，字号越大越明显。
- **根因**：临时画布是"只增不减"复用的，直接 `drawImage(cv, dx, dy, dw, dh)` 会把**整块画布**
  缩放到目标矩形里。
- **解法**：始终给源矩形：`drawImage(src, sx, sy, sw, sh, dx, dy, dw, dh)`。

### 7. 合成入口以单队列判空 → 另一路文字整批不画

- **症状**：场景里只用手绘字（没用矢量字）时，一个字都出不来。
- **根因**：合成函数开头是 `if (!LETTERS.length) return;`，而手绘字排在另一个并行队列里，
  早退把它整批漏掉了。
- **解法**：判空要覆盖**所有**并行队列。以后往合成链上加"新的一类元素"时，
  第一件事就是回来改这个判空（这类 bug 极度安静）。

### 8. 中文的宽度不能按 `size × 字数` 算

- **症状**：逐字排版越到后面越偏，标点处的间距明显不对。
- **解法**：全角按 `size`、半角按 `≈0.56 × size`、空格按 `≈0.34 × size` 分类估算；
  要精确就用 `measureText`。手写体本身不等距，估算反而更"对"。

## 三、时间与坐标（最容易悄悄错的一类）

### 9. 场景里写动画要用**镜头内时间**，不是全局时间

- **症状**：逐字写的文字在第一帧就整句出现，没有"一个字一个字写出来"的过程。
- **根因**：`writeLine(t, ..., t0, per)` 里的 `t0`（起始时刻）是按**镜头起点**算的，
  但传进去的是**全局时间**。于是除了第一个镜头（起点 = 0）之外，其余镜头整句都"早就写完了"。
- **解法**：统一传 `lt`（镜头内时间）。**T0 = 0 的那个镜头会掩盖这个 bug**，
  所以第一个镜头跑通不代表后面没问题 —— 每个镜头都要单独看。

### 10. 手绘字/贴图走 2D 合成层，不参与 p5 的 `push / translate / rotate`

- **症状**：卡片从空中落下的动画里，卡片框在动，**卡片上的手绘字不动**，字提前停在自己的终点位置。
- **根因**：画框走 WebGL（吃矩阵变换），手绘字走 2D 画布（不吃）。
- **解法**：要么在 `push()` 里只放手绘以外的东西、文字等元素**落定之后**再写；
  要么把位移/旋转手动换算给文字。别指望一层的变换能带上另一层。

### 11. 相机内的元素要在相机**开启期间**入队

- **症状**：贴在相机里的图，位置对不上（没跟着相机走）。
- **解法**：需要相机变换的元素（文字、贴图）必须在 `camBegin() / camEnd()` **之间**调用，
  它才能拿到当帧的相机参数去换算；相机结束之后再调用就是在屏幕空间里落点了。

## 四、验证（怎么判断做对了）

### 12. 帧间 PSNR 是"这是动画还是动效"的可复算判据

- **矢量补间**（同一个图形在平移/缩放）：相邻两帧**逐像素完全相同** → PSNR = `inf`。
  这就是"动效"——它没有"重画"。
- **逐帧重画**（每帧由笔触重新堆出来）：相邻两帧 PSNR 落在 **20–25 dB**。
- **用法**：渲两个相邻帧，`ffmpeg -lavfi psnr` 一比就知道。这条比"看着像不像"可靠得多，
  也能用来卡验收门（"整片任意相邻帧都要 ≤ 25 dB"）。

### 13. 改引擎 / 改数据层后要"零漂移"复核

- **做法**：改动**前**先渲一组参考帧；改动**后**同样时间点再渲一遍，逐像素对比，
  设一个噪声门（例如 0.15% 像素、最大值 ≤ 15）。
- **为什么必须**：这类改动（插值模式、字段名、初始化顺序）经常"看上去没动"，
  实际把已经验收过的画面改了；靠肉眼是发现不了的。

### 14. 每镜落定后要抽**全分辨率静帧**看，不要只看缩略接触表

- **教训**：低分辨率接触表上"看着挺挤/挺空"的判断，一半是目测误差；
  反过来说，真正的问题（字太小、元素偏移、边框错位）在缩略图上根本看不出来。
  接触表用来**看结构**，静帧用来**看质量**。

## 五、上一版（DOM 管线）的教训，同样通用

### 15. 命名位数不一致 → 整条"直读帧"通道从未生效

- **症状**：预览"卡得飞起"，以为是渲染性能问题。
- **根因**：预览生成的帧是 5 位编号（`f00000.jpg`），工作台按 4 位读（`f0206.jpg`），
  永远读不到，于是每帧都退回去现场重渲 1920×1080。**卡的不是性能，是命名。**
- **教训**：两个模块约定文件名时，把**位数/格式**写进两边共用的常量，别各写各的。

### 16. 重写文件时丢掉一个启动函数 → 启动即报错，但界面看起来"一半是好的"

- **症状**：页面能开、半边正常、半边不动，不报明显错误。
- **根因**：重写时漏掉了一个启动调用，抛 `ReferenceError`，把后续初始化中断了。
- **解法**：重写整文件后，**先看控制台日志再谈观感**。headless 渲染脚本要把
  `page.on('pageerror')` / `console` 打出来，否则这类错误会一直静默。

---

## 一句话总结

这类活儿里，**最贵的 bug 都是安静的**：丢帧不报错、字不画不报错、时间传错不报错、
读错文件名不报错。所以规矩是 ——
**每个环节都加一道"能拦住它"的显式校验**（帧连续性、帧间 PSNR、零漂移对比、控制台日志），
而不是靠"我看了一遍，好像没问题"。
